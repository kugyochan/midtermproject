## 4단계. 피쉬본 + 5 Why

**머리(문제):** 볼 작품을 고르는 데 너무 오래 걸린다 (저니 3단계, 감정 −2)

| 시각 | 원인 (리뷰 # · 저니 단계) |
|---|---|
| 모바일 UX | 작은 화면에서 후보를 나란히 볼 수 없어 상세를 하나씩 열고 닫는다 (#5 · 3단계) |
| 사용성 | 신호등과 별점의 차이가 설명되지 않아 점수를 해석하기 어렵다 (#1 · 4단계), 자주 쓰는 메뉴 위치가 바뀐다 (#14) |
| 데이터 | 점수가 "다른 사람의 평가" 기준이고 "내 기록과의 관계"가 화면에 없다 (#15 · 2–4단계) |
| API | 화면 하나에 여러 요청이 걸려 상세 진입이 느리다 (#12 · 3단계) |
| 네트워크 | 느릴 때 무엇을 하는 중인지 보이지 않는다 (#2 #12) |
| 프로세스 | 가입을 먼저 요구해 둘러보기 전에 막힌다 (#10 #11 · 1단계), 건의 결과를 알려 주지 않는다 (#8) |

**우선순위 1개: 데이터 — "추천 근거가 화면에 없다".**
- 리뷰 수: 유형 1 사용성·탐색 5건 중 #1 #15가 직접 관련, 저니 최저점(3단계)과 4단계에 모두 걸린다.
- 영향: 근거가 있으면 비교 자체가 줄어든다(왕복 · 대기 · 해석이 함께 준다).
- UI로 고칠 수 있나: 예. 추천 결과와 이유를 json-server에서 GET해 보여 주기만 하면 된다(실제 추천 로직은 만들지 않음). 속도(API · 네트워크)는 서버 문제라 이번 범위에서는 로딩 문구(P01)로만 다룬다.

**5 Why**

1. 왜 고르는 데 오래 걸리나? → 후보 여러 개의 상세를 오가며 직접 비교해야 해서.
2. 왜 직접 비교하나? → 목록의 점수(신호등 · 평균 별점)만으로는 "나에게" 맞는지 판단이 안 돼서 (#1 #15).
3. 왜 판단이 안 되나? → 점수가 다른 사람의 평가이고, 내 기록과 어떻게 이어지는지 보이지 않아서.
4. 왜 보이지 않나? → 앱이 내 기록(본 작품 · 평가)을 갖고 있지만, 추천 화면에서 그것을 "이유"로 꺼내 보여 주지 않아서.
5. 왜 보여 주지 않나? → 화면이 "많이 보여 주기(목록 · 랭킹)"를 위해 설계되어 있고, "근거와 함께 하나를 고르게 돕는" 단계가 기획에 없어서.

**근본 원인:** 추천 화면이 결정이 아니라 탐색을 위해 설계되어 있다.
**v2에서 고칠 것:** A 오늘의 한 편 — A-3 추천 카드(한 편) · A-4 추천 이유(칩 3개 + AI 한 줄) · A-6 다른 후보(최대 3편) · A-3a 내 취향 일치 (P01 · P02 · P03 · P08)

## 5단계. 화면 기획

### 5-1. 화면 흐름

```
[T-1 주 메뉴 탭]  A 오늘의 한 편 ─┬─ (덮기) E 상황 고르기 시트 ─→ A (상황 반영, 1번 후보부터)
                                 ├─ (덮기) G 어디서 볼까 다이얼로그 ─→ (덮기) F 한 줄 평가 시트 ─→ 스낵바
                                 ├─ (쌓기) A' 다른 후보 2 ─→ (쌓기) A' 다른 후보 3
                                 └─ (쌓기) B 작품 상세 ─→ (덮기) F 한 줄 평가 시트
                  C 내 기록 (옆으로: 봤어요 · 보고 싶어요) ─ (쌓기) B 작품 상세
                  D 취향 리포트 ─ (옆으로) A
```

- 쌓기 = Navigator push/pop · 옆으로 = TabBar · 덮기 = showModalBottomSheet / showDialog
- 결정까지 2탭: A 첫 화면 → A-5 "이걸로 볼래요".
